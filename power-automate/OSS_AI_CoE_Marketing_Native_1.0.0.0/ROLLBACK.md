# Stop, rollback and interrupted-run reconciliation

No tenant change was made by the local build. Nothing needs to be undone in Microsoft to use or discard these local review artifacts. The earlier verified frontend, CORE, Node reference, Claude connector and intake releases remain independent.

## If a later native commissioning attempt fails

1. Stop new Marketing requests at the existing controller and verify the exact Marketing flow is OFF. Stop the affected run through the authorized operator route; establish that it ended before any claim release. Do not stop or delete the working intake/governance flows.
2. Retain the exact attempted package, binding/configuration hashes, flow/run IDs, canonical record keys and service ETags, source/version observations, result item IDs and ACL readbacks. Keep business text and provider responses in the approved private store; use content-free incident descriptions.
3. Do not remove/recreate lists, clear unique keys, reset permissions, add an alternate writer, expand sharing or import another naming prefix to evade partial state. Create-only provisioning is not a transaction or an automatic rollback mechanism. Use its private receipts to reconcile partial lists/roles under explicit controller authority.
4. A claimed `writer:marketing` is a safety hold, not an expired lease. Determine whether the original request and retained plan are immutable and consistent; check each planned row against the actual stored hash/content/version. Only the authorized controller can approve an exact-ETag release after the original run is confirmed ended. The flow never performs this operator release itself.
5. If `provider:<request UUID>` is pending and the call outcome is unknown, **do not automatically reissue Claude**. Reconcile the original connector run and any actual retained response. A simulated response, guessed receipt, edited request UUID or a fresh command is not recovery of that invocation.
6. Before any replay can create a new disclosure, recheck current membership, source permissions/content versions, register approval and reviewer authority. Retained drafts and source text are not permanent access authority. If the Results item already has an Author grant, the pre-disclosure private-ACL check holds; breaking already-unique inheritance does not revoke that grant. Reconciliation/revocation requires the approved operator process.
7. Restore only an explicitly approved, hash-identified prior **Marketing** version after reviewing schema/record compatibility. Do not repoint live intake or CORE IDs. Merely importing an OFF package does not prove the existing flow stopped; verify native state again.
8. Resume only after recorded native readback and acceptance of the repaired exact package/configuration. Preserve failed-run and test evidence; do not convert local synthetic receipts into native success.

## What local tests do prove

The executable offline tests interrupt every recorded durable effect in representative manual-draft, provider-draft and review paths. They test no duplicate provider call on restart, private withholding before authorization, exact original-plan continuation after an explicitly simulated operator release, and final version tokens derived from actual fixture readbacks. This is failure-boundary evidence for the code, not proof of Microsoft's native crash semantics or an authorization to perform any recovery write.
